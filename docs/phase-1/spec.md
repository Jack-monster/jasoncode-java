# JasonCode Spec

## 背景

开发者希望在终端中直接与大模型对话，获得类似 Claude Code 的交互体验。JasonCode 是这一方向的第一步：本阶段只做"能对话的终端 AI 助手"，验证配置系统、多协议适配和流式交互三个核心能力，为后续的 agent 能力（工具调用、文件编辑等）打好地基。当前代码库为空，从零开始。

## 目标

- 用户在终端启动 JasonCode 后进入交互式对话界面，可连续进行多轮对话
- AI 回复以流式（SSE）方式逐字打印，thinking 过程实时可见且与正文视觉区分
- 通过统一 YAML 配置接入任意走 OpenAI 或 Anthropic 协议的供应商（含第三方兼容端点），配置内可定义多个供应商并自由切换
- Provider 层抽象为统一接口，新增后端只需实现该接口，不改动调用方代码
- 对话历史在会话内保持完整上下文；历史存储层预留接口，为后续持久化做准备

## 功能需求

- **F1: 配置文件加载**。启动时读取 YAML 配置文件，解析出供应商列表和默认供应商。默认配置路径按顺序搜索用户目录、运行目录；两处均无配置文件时，在用户目录生成配置模板并提示用户填写密钥后重新运行；显式指定路径时直接使用该路径。每个供应商包含：标识名（供应商自己的名字）、协议类型（仅限 openai / anthropic）、模型名、请求地址、认证密钥、是否启用扩展思考（可选）。配置字段错误时，给出清晰的错误提示并退出，不进入对话界面。
- **F2: 供应商选择**。默认使用配置文件指定的供应商；启动时可通过命令行参数临时指定某个已配置的供应商，未配置的名字报错退出。
- **F3: 交互式对话界面**。启动时显示启动 Banner（程序标识 + 清晰的程序名称 + 软件信息区：版本号、定位等）。交互界面采用基于 Lanterna 的**全屏布局**（接管终端备用屏幕，退出时恢复）：自上而下分为对话历史区、单条状态栏、固定底部的输入框；Agent 输出只更新历史区，不覆盖输入框；状态栏就地刷新、全程只有一条；界面四边均有留白（左侧缩进、右侧折行内缩、顶部空行、底部空行），且底部留白更多，内容不贴终端边界。输入提示符为固定带色标识；输入框为固定背景色条（整行背景填充，空输入时也保持背景色并占据固定空间），与输出内容区分；输入框采用**点击聚焦**：进入界面默认未聚焦，点击输入框或直接按键后聚焦才开始接收输入，未聚焦状态下鼠标点击/滚轮/键盘事件不写入任何字符；支持方向键翻看本次输入历史；支持 Shift+Enter/Ctrl+Enter/Alt+Enter 插入换行，实现多行输入（输入框高度随内容扩展，最多 5 行）；支持会话内命令（至少 `/exit`、`/help`）或快捷键退出；输入 `/` 时提供命令补全/候选提示；命令系统可扩展；空输入不触发请求；非终端（管道/哑终端）环境降级为逐行纯文本模式。
- **F4: 流式回复输出**。用户输入后调用大模型 API，回复以流式方式逐块实时呈现到对话历史区，而不是等生成完再一次性返回。输出期间显示正在生成的视觉反馈。
- **F5: 扩展思考展示**。供应商启用 thinking 时，思考内容流式返回并实时显示，思考块与正文块通过**空间结构**区分（层级缩进、边界线区域、空行间距），不使用简单分隔线。思考块为**可折叠组件**（后续工具调用可复用）：思考进行中显示黄色“思考中...”标题并实时展示内容；思考完成后标题变为“思考内容”并自动收起，支持鼠标点击标题展开/收起详情（由 Lanterna 统一处理鼠标事件；终端不支持鼠标时可用 Ctrl+T 切换最近一个折叠块）。对不支持 thinking 的协议，该配置被忽略并给出一次性警告。鼠标/转义序列输入不得污染输入框内容。
- **F9: 输入队列**。流式生成进行中（忙碌）用户仍可继续提交：未被消费的 prompt 在界面中以 queued 状态标记展示；当开始消费时，将所有未消费的 queued 消息合并为一条（换行连接）发起请求，并从界面移除其 queued 标记；状态栏展示当前队列深度。
- **F6: 多轮对话记忆**。同一会话内，每次请求携带完整的历史对话，AI 能引用之前的内容；退出会话后历史不保留。历史存储通过抽象层访问，当前为内存实现，预留替换为持久化实现的接口。
- **F7: 统一 Provider 抽象**。对话请求通过统一的 Provider 接口发出，屏蔽 OpenAI 与 Anthropic 协议的差异（包括流式事件格式、thinking 字段、错误结构）；新增一种协议后端只需新增一个实现，不修改上层代码。
- **F8: 错误处理**。网络错误、认证失败、API 返回错误等场景下，打印可读的错误信息，结束本轮对话但不退出程序，用户可继续输入下一条。

## 非功能需求

- **N1: 流式首字节时延**。用户提交后应尽快开始打印内容（收到第一个流式事件即输出），不因缓冲攒字。
- **N2: 可扩展性**。新增协议后端、替换历史存储实现均通过新增代码完成，不修改既有调用方（对扩展开放、对修改封闭）。
- **N3: 密钥安全**。API key 只存在于配置文件中，程序输出（含错误信息、日志）中不打印完整密钥，最多显示末四位。
- **N4: 终端兼容性**。在常见终端（macOS Terminal、iTerm2）下正常显示颜色、流式输出与 Emoji；Emoji 按双列宽度处理，不会拆分成 surrogate pair；不支持颜色的管道环境下降级为纯文本输出，不产生乱码。全屏 TUI 使用 Lanterna 处理终端差异与鼠标事件。
- **N5: 零外部服务依赖**。除所连的大模型 API 外，程序运行不依赖数据库、后台服务等任何额外组件。
- **N6: 可测试性**。配置解析、协议适配、历史存储等核心逻辑可在不发起真实网络请求的情况下进行单元测试。
- **N7: 终端宽度自适应**。终端窗口宽度改变时，界面输出正确适配新宽度，不出现错位、截断或乱码。
- **N8: 终端状态恢复**。程序退出时完整恢复原有终端状态（光标位置、显示模式等），不破坏用户退出前的终端布局。

## 不做的事

- 不做 tool use / function calling，模型不执行任何工具
- 不做文件读写、代码编辑、命令执行等 agent 能力
- 不做对话历史的落盘持久化（仅预留接口，不提供实现）
- 不做多行输入、Markdown 渲染、代码高亮
- 不做会话内切换供应商（切换需重启时指定）
- 不做自动更新、插件机制、OAuth 等认证方式（仅 API key）
- 不做 OpenAI、Anthropic 之外协议的适配

## 验收标准

- **AC1（F1）**: 配置字段缺失/非法时，程序打印明确的错误原因并退出；用户目录与运行目录均无配置文件时，生成配置模板并提示填写后退出；显式指定的路径不存在时报错退出；以上均不进入对话界面
- **AC2（F2）**: 不带参数启动时使用 default 供应商；指定已配置名称时切换成功；指定不存在的名称时报错退出
- **AC3（F3）**: 启动时可见 Banner（程序标识、版本、供应商）；全屏三区布局生效：流式生成期间输入框始终固定在底部不被覆盖，全程只有一条状态栏且就地刷新；四边留白可见且底部留白更多；输入提示符带色、输入框为背景色条且空输入时背景色仍保持；进入界面未聚焦时鼠标点击/滚轮不向输入框写入任何字符，点击输入框后正常输入；↑/↓ 可翻看输入历史；Shift+Enter/Ctrl+Enter/Alt+Enter 可插入换行实现多行输入；输入 `/` 后可看到命令候选；`/help` 列出可用命令；`/exit` 与 Ctrl+C/D 均可退出；退出后终端布局完好（对应 N8）；管道环境降级纯文本无乱码
- **AC4（F4）**: 提交消息后回复逐块实时打印，肉眼可见流式过程，而非长时间空白后一次性出现全文
- **AC5（F5）**: thinking 开启时：思考中显示黄色“思考中...”标题并实时可见内容；完成后标题变为“思考内容”并自动收起；鼠标点击标题（或 Ctrl+T）可展开/收起详情；鼠标点击/滑动不向输入框写入任何字符；思考块（边界线缩进区）与正文（顶层）空间结构分离；openai 协议配置 thinking 时收到警告且正常对话
- **AC6（F6）**: 第二轮对话引用第一轮内容时 AI 能正确回应（如第一轮告知一个事实，第二轮就该事实提问）
- **AC7（F7）**: 同一个对话界面逻辑，分别对接 OpenAI 协议和 Anthropic 协议供应商均能完成流式对话；新增第三种协议时上层代码零改动
- **AC8（F8）**: 断网或提供错误 API key 时，程序打印可读错误且不退出，可继续下一轮输入
- **AC9（N3）**: 任何错误输出中不出现完整 API key
- **AC10（N4/N7）**: 管道重定向下无乱码；对话过程中改变终端宽度，界面重新布局且后续输出显示正常
- **AC11（F9）**: 生成进行中连续提交多条 prompt → 界面出现带 queued 标记的排队项且状态栏队列深度随之变化；开始消费时所有排队消息合并为一条请求，queued 标记从界面消失；后续对话上下文包含全部合并内容
